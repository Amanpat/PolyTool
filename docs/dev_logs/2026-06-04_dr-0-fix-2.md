## Blocker 1 — one wallet can exceed the 60s grace (request-granularity cancel)

Re-review math: `should_stop` was checked only BETWEEN wallets, but one hung
endpoint is `4 attempts × 15s timeout + (1+2+4)s backoff = 67s` — past the 60s
Docker stop grace → SIGKILL mid-wallet. The original blocker reborn at request
granularity.

Fix — thread the stop flag into the scan request/retry loop so a stop aborts the
IN-FLIGHT request/retry, bounding stop latency to ~one request timeout:

- `tools/cli/scan.py`: added a process-global, OFF-by-default cancellation hook
  (`set_cancel_check`/`clear_cancel_check`/`_scan_cancelled`) + `ScanCancelled`.
  `request_with_retry()` and `get_json()` now call `_raise_if_cancelled("before
  request")` before each attempt and use `_cancellable_sleep()` (sliced, aborts
  within ≤0.2s) for backoff. The only uninterruptible piece is one in-flight
  `requests` call, already bounded by the per-request timeout. **The foreground
  `wallet-scan` (DR-2) path never installs the hook, so its behavior is
  byte-for-byte unchanged.** (Confirmed: `run_scan` — the drain path — makes ALL
  HTTP via `post_json`/`get_json`; the re-review's CLV/CLOB concern at scan.py:1144
  is a different, non-`run_scan` code path and is not in the drain.)
- `packages/polymarket/discovery/scan_worker.py`: `ScanWorker.run` installs the
  hook (= `should_stop`) around the drain when `should_stop` is provided, and
  catches `ScanCancelled` as a CLEAN abort — the partial wallet is NOT ingested,
  NOT failed, and its lease is released back to pending (no poison-pill attempt
  burned) via the new `ScanQueueManager.release()`. It then stops (no new wallet).
- `packages/polymarket/discovery/scan_queue.py`: new `release()` — leased → pending
  without incrementing `attempt_count` (distinct from `fail`/`requeue_expired_leases`,
  which count a crash).

**Real test** (`TestRequestGranularityCancel::test_stop_aborts_in_flight_request_and_does_not_ingest`):
a real `ScanWorker` drives the real `scan.py` retry/backoff loop against a real
hanging TCP server (accepts, never responds → per-attempt ReadTimeout). A stop
flag flips ~0.4s in. Asserts: abort in **1.73s wall (test bound `< 4.0s`)** vs the
7.5s uncancelled budget; `ingested == []`; `result.cancelled == 1`; item back to
`pending` with `attempt_count == 0`. PASS. Supporting: `test_cancellable_sleep_aborts_backoff_fast`
(backoff aborts in <1s of a 10s sleep), `test_foreground_path_has_no_cancel_hook`
(DR-2 gate). PASS.

## Blocker 2 — unsupervised daemon heartbeat could die silently

Re-review: the heartbeat ran on a daemon thread with no supervision; if it died
while the main drainer lived, mtime froze → after ~180s a second worker reclaims
a LIVE lock → double drain.

Fix — remove the background thread; refresh from the holder's MAIN loop:

- `packages/polymarket/discovery/worker_lock.py`: deleted `start_heartbeat` /
  `_beat_loop` / the daemon thread / `_thread` / `_stop`. `WorkerLock` keeps only
  `beat()` (bump mtime) and `release()`. `acquire_worker_lock` no longer takes
  `start_heartbeat` and starts no thread. Because the refresher IS the holder's
  own main loop, there is no separate thread that can die independently: holder
  alive → it beats; holder dead → it stops beating and the lock correctly goes
  stale.
- `packages/research/scheduling/discovery_scheduler.py`: `run_scheduler_blocking`
  gained `heartbeat=` and calls it on every poll-wait cycle (default 60s, on the
  main thread, even while a drain runs on a job thread). The wait loop now also
  exits on `drain_stop_requested()` (in production the signal handler sets both
  that and `stop_event`, so this is equivalent + responsive + testable).
- `tools/cli/discovery.py`: `_scheduler_start` passes `heartbeat=lock.beat`; the
  manual worker passes `heartbeat=lock.beat` to `worker.run`, which beats between
  wallets so a long bounded drain on the main thread never goes stale.

**Real tests** (`TestHeartbeatSupervision`):
`test_acquire_starts_no_background_thread` — `threading.active_count()` is
unchanged across acquire and `WorkerLock` has no `_thread`/`_stop` (there is
literally no thread to die). `test_scheduler_main_loop_refreshes_lock` — runs the
real `run_scheduler_blocking`; the lock mtime is refreshed from the main loop
within the stale window while it blocks, then a cooperative stop exits it (rc 0).
`test_manual_worker_beats_between_wallets` — the real `ScanWorker.run` refreshes
the lock between wallets. All PASS.

## SHOULD-FIX D — clock skew: accept + document, do not gate
`worker_lock.py` module docstring now states the SAME-HOST assumption explicitly:
staleness compares a reader's `time.time()` to the file mtime, which is safe only
on one host (the scheduler container and a manual worker share the host kernel
clock via the `./artifacts:/app/artifacts` bind mount — containers share the host
clock; no skew). We deliberately do not gate on or correct skew; revisit only if a
worker ever runs on a separate machine (not a supported topology).
