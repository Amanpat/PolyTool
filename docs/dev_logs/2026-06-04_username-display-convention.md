### Root-cause attribution

- **CH "auth failure" (UPDATE #5) = env propagation, NOT a stale-volume credential mismatch.** The provisioned password already equals `.env` (`admin`). The scan/export CLI entrypoints fall back to the **forbidden** default `"polytool_admin"` when `CLICKHOUSE_PASSWORD` is unset — `tools/cli/scan.py:86`, `export_dossier.py:29`, `export_clickhouse.py:22`, `examine.py:54` all use `os.getenv("CLICKHOUSE_PASSWORD", "polytool_admin")`. `"polytool_admin"` is exactly the value that returns `Code: 516`. Run host-side without the env → 516; run inside the container (env present) → works. This violates the CLAUDE.md ClickHouse-auth rule ("never use a hardcoded fallback like `polytool_admin`; fail-fast if unset").
- **Realized-PnL=0 (UPDATE #5) = same env-propagation cause, NOT unset resolution providers.** Providers are set; resolutions resolved (0% unknown). When the scan can't read `user_trades_resolved`/`user_positions_resolved` (516), realized falls to 0; with env present (the run that wrote `e2d340a3…`) realized is fully differentiated. The referenced artifact **does not reproduce** PnL=0.

### Recommendation (OPERATOR-ONLY — not executed)

- **Fix = env propagation:** run `wallet-scan` with `CLICKHOUSE_PASSWORD` in its environment — inside the `discovery-scheduler` container, via `docker compose run`, by sourcing `.env` into the host shell, or `--clickhouse-password`.

## STEP 1 — Username display convention (implemented)

**Canonical rule:** `wallet_id` (the `0x` address) is the only key/slug/join. `username` is display-only (mutable, non-unique, often auto-generated). `display_name(...)` output is intentionally lossy and must NEVER be used as a key.

### Files changed

1. **`polytool/user_context.py`** — new display helpers:
   - `display_name(username, wallet_id)` — the single identity-display helper. Returns a real handle; falls back to a truncated wallet ID when the username is empty/null OR auto-generated.
   - `is_autogenerated_username(username, wallet_id=None)` — empty / equals the address / bare 40-hex `0x` / API placeholder `0x<hex>-<digits>`.
   - `truncate_wallet(wallet_id)` → `0xa380...21ff` (ASCII `...`, Windows cp1252-safe).

2. **`packages/polymarket/discovery/leaderboard_export.py`** — the export→scan handoff:
   - `export_leaderboard_entries()` returns `[{wallet, username}]` (camelCase `userName` → snake fallbacks); `export_leaderboard_addresses()` is now a thin wrapper (unchanged behaviour).
   - `write_username_sidecar()` + `username_sidecar_path()` write `<input>.usernames.json` (`{lowercased_wallet: username}`, non-empty only). The input file stays bare addresses → **100% backward-compatible**; the sidecar is purely additive.
   - `export_to_file()` now also writes the sidecar and reports `usernames_written` / `username_sidecar_path`.

3. **`tools/cli/discovery.py`** — `export-leaderboard` prints the sidecar line when usernames were written.

4. **`tools/cli/wallet_scan.py`** — the wallet-scan path:
   - `_load_username_sidecar()` auto-discovers `<input>.usernames.json` (missing/garbled → empty map → bare-address input still scans).
   - `parse_input_file(..., username_map=None)` attaches a display `username` to each entry (default `""`); `identifier` stays canonical.
   - `_resolve_wallet_id()` → canonical wallet (dossier `proxy_wallet`, else a wallet identifier; never a username).
   - `_stamp_dossier_username()` carries the handoff username into `dossier.json` header (never overwrites a real scanned handle; non-fatal) — completes export→scan→**dossier**.
   - `_success_result` / `_failure_result` now carry `wallet_id`, `username`, and `display_name`; leaderboard rows + `leaderboard.md` add a **User** (display_name) column AND a separate **Wallet ID** column (Decision #5: never collapsed). `slug` stays wallet-keyed; dossier dirs stay wallet-keyed.

5. **`tools/cli/scan.py`** — the `Scan complete / Username:` summary now uses `display_name(...)`, replacing the old `resolve_response.username or config["user"]` default that printed the raw full address as the "username".
